Hey folks,

I'd like to add that this is a *critical* bug, and it occurs on 10.3, 
too -- maybe the new findutils version introduce the problem?

Today and yesterday my HD run full. The problem is that apparently, for 
updatedb /dev/fd/3 is an alias for /. So when updatedb scans my FS, it 
gets into an infinite recursion loop. In my case it created about 15 GB 
of temp files (indexing the "infinitely many files" on my HD), before 
it run out of HD space.

Running out of HD space is rather dangerous, if you notice it too late 
it can cause data loss (10.3 really tries to warn you about this, but 
if your machine is running while you are absent, as in my case, you can 
be too late)...
