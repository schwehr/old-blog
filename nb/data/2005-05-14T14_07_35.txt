Math.exp() was that it is faster.  I figured I would do a quick check
since I will be doing a lot of fitting to exponential functions.  I
got that Numeric is <b>much</b> slower.  This is on a 1.5 GHz G4 Ti
laptop with 1GB ram and 10.3.9 using python 2.4.1-1 from fink and
numeric-py24 23.8-11.  First the code.  It maybe that there is some
internal optimization that I am cancelling out by calling exp this
way.

You just can not get any simpler than that.  I do not think that
python does any optimization that would just throw out the exp call
since it is really a no-op.  With C++, I would have to go look at the
generated assembly to make sure the call actually happened.  Now for
the results:
<pre>
./speed.py 
 totalMath    =  0.064
 totalNumeric =  0.192
</pre>
Ouch :(  I did find one thing that is much better about the Numeric
exp.  If you give a value too large, the Numeric.exp() call returns
inf, while math.exp() throws OverflowError.  I suppose which is better
depends on what you are trying to do.  e.g.:
<pre>
  max=700
  print max
  print Numeric.exp(max)
  print math.exp(max)

  max=800
  print max
  print Numeric.exp(max)
  print math.exp(max)
</pre>
gives
<pre>
  700
  1.01423205474e+304
  1.01423205474e+304
  800
  inf
  Traceback (most recent call last):
    File "./speed.py", line 17, in ?
      print math.exp(max)
  OverflowError: math range error
</pre>
