Now I am actually working on data that I know is of use to my thesis.
I need to make the plot look 'reel purdy' this evening.  Here are some
notes on how I am doing this.

I am starting with the same xstar file that I was working with
yesterday: bpsio04L04.xstar.  It would be nice to have a little option
that would calculate the bounding box for a line, but I do not have
that at the moment.  What I do have is segysqldist.py.  First I need a
database just for this line (so it will go quickly).
<pre>
  &gt; segysql.py -f bpsio04L04.db  -d xstar   bpsio04L04.xstar
  &gt; ls -l bpsio04L04.db
    -rw-r--r--    1 schwehr  staff    27310080 Jun 22 19:18 bpsio04L04.db
</pre>
Now I would like to see how this line compares to the core 4
location.  My new app segysqldist.py is designed just for this job.
<pre>
  &gt; segysqldist.py -x -120.05716666 -y 34.37899999 -n 100 \
        -d line.dat -f bpsio04L04.db

The program created 3 new files.  point.dat contains the location that
was specified on the command line to search for.  results-lonlat.dat
has the closest 100 shots (ignoring all the shots with duplicate
locations).  Finally line.dat has a subsampled set of x,y pairs of the
input data so that we can see the track lines.  Now I need to use my
trusty friend gnuplot to see what the world looks like.
<pre>
  gnuplot&gt; plot 'line.dat','results-lonlat.dat','coreloc.dat' 
  gnuplot&gt; set label 4 '4' at -120.055,34.37899999
  gnuplot&gt; set terminal png
  gnuplot&gt; set output '4-distance.png'
  gnuplot&gt; plot 'line.dat','results-lonlat.dat','coreloc.dat'
</pre>
In the graph, the green section (I know... red/green = bad) marks the
closest 100 shot locations that surround core 4.<br>

There is a handy program called <em>minmax</em> in GMT that will
summarize the situation for us!
<pre>
&gt; minmax results-lonlat.dat 

results-lonlat.dat: N = 100     
   <-120.059/-120.055>   <34.3672/34.3908>  <0.000124/0.012083>
   <1/1>                 <81820/84782>      <4001/9921>
</pre>
This means that the key range in pltsegy is in the neighborhood of
shotpoints 81820 to 84782.  I am going to round this to be a nicer
range for plotting in pltsegy.
<pre>
  81800 to 84800
</pre>
Hopefully my makepltsegy.py script will actually work to give a plot
in this range.  I need to adjust <em>sioseis-wbt.bash</em> to only
spit out this region for the maximum turnaround time.
<pre>
  declare -r FNO="81800"
  declare -r LNO="84800"
  declare -r INFILE=$1
  declare -r OUTFILE=$2
  declare -r WBTFILE=$3
</pre>
And run sioseis something like this:
<pre>
  &gt; ./sioseis-wbt.bash bpsio04L04.sgy bpsio04L04-wbt03.sgy \
                     bpsio04L04-02.h2o

  &gt; ls -l *.sgy
-rwxr-xr-x    1 schwehr  staff    81956368 Jun 21 11:31 bpsio04L04-wbt01.sgy

-rwxr-xr-x    1 schwehr  staff    24890896 Jun 22 20:20 bpsio04L04-wbt03.sgy
</pre>

I am not sure what that means.  My previous pltsegy file still works

<pre>
plot
       dtfile = bpsio04L04-wbt03.sgy;
       plfile = test.ps;

       tmark = 0.01;

Oh... typo!  Should be timscal, not tim<b>e</b>scal.  Got it.  Now I have a
happy pltsegy.  To make the plot take up more of the horizontal screen
space I had to adjust the horizontal shot spacing (spa).
<pre>
  &gt; makepltsegy.py -o test.pltsegy -p test.ps -i bpsio04L04-wbt03.sgy \
       -s 81800 -S 84800 --spa=0.100 --timscal=200
  &gt; rm -f sort*; pltsegy test.pltsegy
</pre>
Works!
