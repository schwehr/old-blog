I know that <em>lines of code</em> is a horrible metric, but I felt
like taking a 15 minute break to see how many lines of code are in my
thesis that are written by me.  There are a couple of big reasons why lines of codes sucks: 
<ul>
 <li> I can do more in python in one line than with C (excepting macro craziness)
 <li> There are a lot of embedded documentation strings
 <li> What if I like or dislike whitespace lines?
 <li> What if a project autogenerates files in certain languages?  I do this for gnuplot in my thesis.
</ul>
I did an egrep -v on these values:
<pre>
SKIP:='sioseis|dac-cmds|pltsegy|xsonar|pmag-py|giv|\~|bak|xvpics|\,v$$|\.in|foo|Away'
</pre>

    C code: 4768
</pre>
The big surprise for me is how much straight c code I still have
