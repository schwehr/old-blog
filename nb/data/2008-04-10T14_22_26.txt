AUTHOR: Kurt

DESC: what I think
-----
BODY:
I just got asked what I think of <a
href="http://trac.edgewall.org/">trac</a>.  Here are some of my
thoughts.
<ul>
  <li>Development has been quite rapid.  You probably want to start
  off with the 0.11 betas.</li>
  <li>The integration between changes in svn, bugs, and the wiki is
  AWESOME!</li>
  <li>Make sure to run the svn and trac setups on the same server or
  you will have to use something like <a
  href="http://svk.bestpractical.com/view/HomePage">svk</a> to sync
  from your svn server to trac which is slow and annoying, but works.
  </li>
  <li>I've had a little trouble with getting some of the plugins to be
  totally happy, but haven't really needed the plugins much.  Just use
  the admin one </li>
  <li>The wiki is sufficient, but after doing a serious roll out of
      mediawiki for our non-dev folks, I wish trac was as powerful.
      However, for coding issues trac is better than mediawiki.  
      Attaching files is clunky in trac, but it does work.</li>
  <li>I compared Trac to <a href="http://www.mantisbt.org/">Mantis</a>
  and <a href="http://www.bugzilla.org/">Bugzilla</a> in 2006 and Trac
  won hands down</li>
  <li> Do not use sqlite2... sqlite3 is way faster and more better</li>
  <li> Would suggest switching away from sqlite3 to a real server
       based db as sqlite3 is pretty wimpy and can't deal with
       multiple readers.  If you want to use the db outside of the
       straight trac app, then a real db is a win.  The db layout is
       really simple to understand, so writing things like django code
       would be pretty easy/cool... and only thought of that right
       now.  Wonder if we could blend the auth system from django into
       trac so that trac would use the django tables.  Guess what...
       A little searching got me <a href="http://trac-hacks.org/wiki/DjangoAuthIntegration">DjangoAuthIntegration</a> [Track-Hacks.org]
  </li>
  <li> When I first looked at 0.9 it didn't support postgresql, but it
       looks like 0.11b2 is all set for postgresql</li>
</ul>
