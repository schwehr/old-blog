Monica recently wrote on her blog about picking a programming
language: <a href="http://the-moni-blog.blogspot.com/2008/06/perls-pythons-and-rs.html">Perls,
Pythons, and Rs...</a>  Here my thoughts on some things to consider
when choosing a programming language (and code libraries too). 
The answers to these questions and how to prioritize them will vary
greatly from person to person even within the same group or company. 
<ul>
  <li>How is it to program in the language?  Is it fun or painful?</li>
  <li>How maintainable will the code be?</li>
  <li>What platforms will your code be able to work on (Mac, Linux, Windows, etc.)</li>
  <li>What are the options for compilers and interpreters?</li>
  <li>Will you need a license / $$$ to develop and/or run the code?</li>
  <li>How mature is the language?  Too new can be trouble</li>
  <li>How many people can you get access to discuss issues with?  Locally? Via the internet?</li>
  <li>What kind of tools support the language?  Debuggers, editors, development environment?</li>
  <li>Will it perform well enough for the task(s) at hand.</li>
  <li>What is the expected lifetime of the project, programming language, and any company that controls it?</li>
  <li>Can you or someone you pay get access to the internals?</li>
  <li>Can it run without a graphical interface?</li>
  <li>Does it support graphical interfaces?</li>
  <li>Can it talk to databases, network protocols, and hardware that you require?</li>
  <li>Job requirements?  (e.g. are you required to use ADA or COBOL?)</li>
  <li>Do you have a pre-existing code base?  Can you start fresh?</li>
  <li>How will this programming language impact your career?</li>
  <li>Can you use this programming language for other tasks?</li>
  <li>What is the labor pool like?  Can you find someone competent to hire
  if you need help and can afford it?
  <li>Is the source code diff'able?  How can you compare two versions of LabView VI's?</li>
  <li>Are you up for learning a new language?  How soon do you have to be productive?</li>
  <li>Can the language interface with your other tools?</li>
</ul>
I can only answer the above in my own frame of reference and for right
now.  A key point is that I have to work with multiple languages
daily!
<ol>
  <li>python is my primary language.  It's a low stress, fun language that gets the jobs done</li>
  <li>bash/sh gets a lot of use, but I try to default back to python when ever possible</li>
  <li>SQL is critical, as putting my data in PostgreSQL/PostGIS keeps me sane</li>
  <li>C++ when I have to for speed critical loops and hardware interfaces to write.  I try to use it as little as possible</li>
  <li>make helps me keep tasks straight</li>
  <li>I'm working on my JavaScript/AJAX/JQuery skills as that makes the web go better</li>
  <li>XML and XHTML for data organization - Basic HTML knowledge is a must</li>
</ol>
Why python?  That's a tough one to boil down, but here is an unordered overview of my current view:
<ul>
  <li>It's fun/relaxing compared to other languages I know</li>
  <li>Expressive and powerful syntax that lets me write fewer lines.  Strong but easy to use object-oriented syntax and namespaces </li>
  <li>Easy to read and I like the indentation for block structures (I hated the indentation thing for about two days back in 1996)</li>
  <li>Lots of easy to use database interfaces that all work the same way</li>
  <li>Advanced database interfaces if I need them</li>
  <li>For scientific programming, I have access to scipy, scientificpython, gsl (gnu scientific library), <b>R</b>, proj, and matplotlib (plus many more)</li>
  <li>Integration with C and C++ is very good.  ctypes for easy tasks, swig for big pre-existing libraries, and CPython for total control</li>
  <li>Making reusable python packages is easy</li>
  <li>Friendly, open community of programmers</li>
  <li>Well supported on most OSes and comes with all Macs and most linux distributions</li>
  <li>Easier to teach good programming skills than most other languages</li>
  <li>Lots of graphical interface libraries</li>
  <li>Python scales well to very large programs (my largest to date is 60K lines of code and that is small compared to many other projects)</li>
  <li>Python is open source with a liberal license and there are a lot of other python programmers out there</li>
  <li>No license file or dongle to fail</li>
</ul>
Python is not perfect and neither are any of the other programming
languages, but python works very well for me.  Remember too that speed 
of a system is often more about algorithms and data structures.  As
long as you have some way to create more complex data structures (e.g.
with easy access to C/C++), then you can find the areas of code with
speed problems and address it.

<b>Perl vrs Python</b>

I have only one real complaint about python where perl is better.  In
perl, replacing some text throughout a file is a simple one liner.
Here I am replacing SGI rgb image files with jpeg images in a bunch
of VRML files:
<pre>% <b>perl -pi -e 's|T.rgb|T.jpg|g' *.wrl</b></pre>
How can I do this as a one liner in python?
