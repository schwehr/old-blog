For each of our multibeam surveys, we need to create a metadata file.  For
the recent Summer Hydro course, CCOM is generating a metadata file for each
line of the data.  I've been interested in taking a crack at metadata for 
a while as it chews up a lot of time, it labor intensive, and prone to 
errors.  Briana and Brian C. did a first pass of scripting the processes
and I used their efforts as a reference in addition to help from Monica,
Roxie, and indirectly Jim G.  My approach is to use MB-System to read the
data from each line and then fill in a user supplied template with the
information that changes from line to line.  MB-System can read the .raw.all
files generated by the EM-3002D used on the survey.

For these lines, I've been told that the metadata should have the
positions of the first and last shot rather than the bounding box.  I
really want this info in python, so I used <a
href="http://www.python.org/doc/2.5.2/lib/os-newstreams.html">os.popen</a>
to capture the output that goes to stdout.
<pre><tt><b><font color="#0000FF">def</font></b> <b><font color="#000000">get_nav_info</font></b><font color="#990000">(</font>filename<font color="#990000">):</font>
<i><font color="#9A1900">    'Use MB System to read the multibeam navigation data'</font></i>
    start<font color="#990000">=</font>None
    <b><font color="#0000FF">for</font></b> line <b><font color="#0000FF">in</font></b> os<font color="#990000">.</font><b><font color="#000000">popen</font></b><font color="#990000">(</font><font color="#FF0000">"mbnavlist  -OMXY -I%s"</font> <font color="#990000">%</font> filename<font color="#990000">):</font>
        unix_utc_timestamp<font color="#990000">,</font>x<font color="#990000">,</font>y <font color="#990000">=</font> line<font color="#990000">.</font><b><font color="#000000">split</font></b><font color="#990000">()</font>
        <b><font color="#0000FF">if</font></b> <b><font color="#0000FF">not</font></b> start<font color="#990000">:</font>
            start <font color="#990000">=</font> unix_utc_timestamp
            start_x <font color="#990000">=</font> x
            start_y <font color="#990000">=</font> y
        end <font color="#990000">=</font> unix_utc_timestamp
        end_x <font color="#990000">=</font> x
        end_y <font color="#990000">=</font> y
    <b><font color="#0000FF">return</font></b> <font color="#990000">{</font><font color="#FF0000">'start'</font><font color="#990000">:</font>start<font color="#990000">,</font><font color="#FF0000">'start_x'</font><font color="#990000">:</font>start_x<font color="#990000">,</font><font color="#FF0000">'start_y'</font><font color="#990000">:</font>start_y<font color="#990000">,</font><font color="#FF0000">'end'</font><font color="#990000">:</font>end<font color="#990000">,</font><font color="#FF0000">'end_x'</font><font color="#990000">:</font>end_x<font color="#990000">,</font><font color="#FF0000">'end_y'</font><font color="#990000">:</font>end_y<font color="#990000">}</font>
</tt></pre>
The above code captures the first and last lines of the nav, returning
it in a dictionary.  I need a bit more information and I want to have the
start and end times as python objects, so I need to clean things up before
I get to the templating part.
<pre><tt><b><font color="#000080">import</font></b> os<font color="#990000">,</font>stat<font color="#990000">,</font>datetime
line_info <font color="#990000">=</font> <b><font color="#000000">get_nav_info</font></b><font color="#990000">(</font>filename<font color="#990000">)</font>
line_info<font color="#990000">[</font><font color="#FF0000">'start'</font><font color="#990000">]</font> <font color="#990000">=</font> datetime<font color="#990000">.</font>datetime<font color="#990000">.</font><b><font color="#000000">utcfromtimestamp</font></b><font color="#990000">(</font><b><font color="#000000">float</font></b><font color="#990000">(</font>line_info<font color="#990000">[</font><font color="#FF0000">'start'</font><font color="#990000">]))</font>
line_info<font color="#990000">[</font><font color="#FF0000">'end'</font><font color="#990000">]</font>   <font color="#990000">=</font> datetime<font color="#990000">.</font>datetime<font color="#990000">.</font><b><font color="#000000">utcfromtimestamp</font></b><font color="#990000">(</font><b><font color="#000000">float</font></b><font color="#990000">(</font>line_info<font color="#990000">[</font><font color="#FF0000">'end'</font><font color="#990000">]))</font>
filesize <font color="#990000">=</font> os<font color="#990000">.</font><b><font color="#000000">stat</font></b><font color="#990000">(</font>filename<font color="#990000">)[</font>stat<font color="#990000">.</font>ST_SIZE<font color="#990000">]</font>/1000000. # Make it MB
</tt></pre>
The results from get_nav_info are all strings.  Therefor, I have to
convert the start and end unix UTC timestamps to floats before 
converting them to datetime objects.  <b>os.stat</b> gets the file
size in bytes.  Now I am ready to open the template and use it with
<a href="http://www.cheetahtemplate.org/">Cheetah</a> to have the values filled in.
<pre>import Cheetah.Template 
template=open('template.cheetah').read()
t = Cheetah.Template.Template(template,
                              searchList=[line_info,
                                          {'filename':filename,
                                           'filesize':filesize}
                                         ]
                             )
open(filename+'.metadata','w').write(str(t)) # "Render" the template to a file</pre>

You can now generate a .metadata file:
<pre>% <b>./metadata.py -t metadata.tmpl *.all</b></pre>
This solution still leaves a lot of issues up in the air and does not
guide you through creating this template, but it removes the error
prone human data entry for the times and positions.

The next question is if MB-System can read the Caris formatted lines.
I believe it can, but have not tried.  I think this might be the
same format:
<pre>% <b>man mbio</b>

My first impressions of Cheetah is that I like it and it is 
fairly simple to use.  There are lots of templating engines
out there and I am considering rewriting my AIS XML to Python
compiler in a templating engine.

Also, it is fairly easy to use mbnavlist to feed my kml Google Earth
generation script.
<pre>% <b>mbnavlist -OXYM -I0162_20080616_161142_RVCS.all | awk '{print $1,$2,"RVCS",$3}' > 0162_20080616_161142_RVCS.all.xymt</b>
% <b>xymt2kml 0162_20080616_161142_RVCS.all.xymt > 0162_20080616_161142_RVCS.all.kml</b>
% <b>open 0162_20080616_161142_RVCS.all.kml</b>
</pre>

<b>Update:</b> Some comments from Dale C.:
<pre>
This is an excellent start on a good strategy, but it is very subject
to data quality issues associated w/ real data that has not yet been
quality checked, such as (but not limited to):
.
- bad nav (a single bad ping in the middle of the file can make mess)
- some data file types don't always produce a lat & long for the first
  ping (record) in a file
.
Some error/bounds checking would make this more robust.
.
With regard to the "reading Caris format", the internal Caris formats
are proprietary. However, Caris can export gsf-format files and that
should work.</pre>
