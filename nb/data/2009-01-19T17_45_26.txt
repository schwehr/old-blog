I have some EBCDIC Knudsen data that I need to read.  Time to do a
better job of using python to detect and use EBCDIC, preferably
without the user having to do anything.  Python has a <a
href="http://docs.python.org/library/codecs.html">codec module</a>,
for which I found a <a
href="http://effbot.org/librarybook/codecs.htm">simple example</a>.
The list of codecs on the python codec module page is confusing.
It was only after working on this post that I discovered that I need
"<i>cp037 IBM037, IBM039</i>".  Here is how I went about trying to figure 
out this whole system.  First, I wanted to see what happened when I
loaded the SEGY text header (which in this case is EBCDIC).
<pre>% python
&gt;&gt;&gt; import codecs
&gt;&gt;&gt; f = codecs.open('foo.sgy', 'r', 'ascii')
&gt;&gt;&gt; hdr = f.read(3200)
UnicodeDecodeError: 'ascii' codec can't decode byte 0xc3 in position 0: ordinal not in range(128)</pre>

Looking at what those values in the <a
href="http://docs.python.org/library/codecs.html#id3">table of
Standard Encodings</a>, it is clear that we only want cp027, which is
EBCDIC in English.  We could also use cp437, cp424, cp500, cp875, 
cp1026, or cp1140 as fallbacks.  However, quopri_codec and 
string_escape return junk.

To see what cp037 looks like, take a look at this page:
<a href="http://unicode.org/Public/MAPPINGS/VENDORS/MICSFT/EBCDIC/CP037.TXT">http://unicode.org/Public/MAPPINGS/VENDORS/MICSFT/EBCDIC/CP037.TXT</a>
