Based on what I've seen, I would recommend avoiding Bath2000 systems.
Or is there some way to configure the system to write proper segy?

I've been spending some time with ODEC Bathy 2000 seismic data.
Thanks to Paul Henkart for helping me understand the ODEC format.
ODEC .dat files are SEG-Y like files.  They use coordinate units 3,
but set the field to 0.  The x and y are IEEE float numbers.  All byte
orders are backwards.  Each trace has a trailer of 320 bytes.  I don't
have info on what is in those bytes.  There appears to be some other
sort of data between traces in some ODEC files.  Both simplesegy and sioseis
do not read past whatever it is.  Sonarweb does read the file.

If anyone cares, I have sample file that works for sonarweb but not
the others: <a
href="http://vislab-ccom.unh.edu/~schwehr/software/simplesegy/data/y0902-01.dat.bz2">y0902-01.dat.bz2</a>

The command that I used to read odec as follows.  The <i>-T 320</i> and <i>-B</i>
<pre>% <b>segy-info -s -T 320 -B Bathy2000/y0902-01.dat -f kml > y0902-01.dat.kml</a></b></pre>
Here is what I got with simplesegy and sioseis converted segy.
<img title="Bathy 2000" withgrayborder="True" src="http://schwehr.org/blog/attachments/2009-02/odec-bathy2000-ge.png"/>

Here is the conversion from .dat ODEC to segy with sioseis:
<pre>!/usr/bin/env bash
<!-- -->
sioseis &lt;&lt;EOF
procs diskin header diskoa end
diskin
   ipath y0902-01.dat format odec end
end
header
    i45 = 3 end
end
prout
      indices l3 l4 l19 l20 l21 l22
   format (6(1x,F15.0))
   fno 0 lno 10
  end
end
diskoa
   opath y0902-01.segy end
end
end
EOF</pre>
