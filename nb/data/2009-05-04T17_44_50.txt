Update 5/5: Val found this that implies that a BIOS update would do
it: <a
href="http://www.linuxquestions.org/questions/linux-hardware-18/cant-reboot-intel-5400-based-systems-with-fedora-10-720451/">Can't
reboot "intel 5400" based systems with FEDORA 10</a>.  Les updated the
BIOS and it still wouldn't reboot.  We went to CentOS 5.3 and it
reboots just fine.  The other CCOM servers are pretty much all CentOS,
so this will make it easier for them to admin.

We've got a linux server that I just upgraded to Ubuntu 9.04.  When I
rebooted, it hung then it tried to reboot the machine.  I tried
reinstalling the kernel and modutils.  I also tried putting "blacklist
iTCO_wdt" into /etc/modprobe.d/blacklist-watchdog to get rid of the
watchdog as suggesting in <a
href="https://bugs.launchpad.net/ubuntu/+bug/218357 ">bug report
218357</a>.  With no luck.  This is an 8-core Xenon Dell Precision
5400 with Raid 1 on two .75 TB drives.  I finally bit the bullet and
tried <a href="https://wiki.ubuntu.com/KernelTeam/GitKernelBuild">making a custom kernel</a>...
<pre>% <b>sudo apt-get install wget git-core kernel-package fakeroot build-essential ncurses-dev</b>
% <b>wget http://www.pair.lkams.kernel.org/pub/linux/kernel/v2.6/linux-2.6.29.2.tar.bz2</b>
% <b>tar xf linux-2.6.29.2.tar.bz2</b>
% <b>cd linux-2.6.29.2</b>
% <b>make menuconfig</b>
% <b>make-kpkg clean</b>
% <b>CONCURRENCY_LEVEL=10 fakeroot make-kpkg --initrd --append-to-version=-custom kernel_image kernel_headers</b>
# Wait a while
% <b>cd ..</b>
% <b>sudo dpkg -i linux-image-2.6.29.2-custom_2.6.29.2-custom-10.00.Custom_i386.deb</b>
% <b>sudo dpkg -i linux-headers-2.6.29.2-custom_2.6.29.2-custom-10.00.Custom_i386.deb</b></pre>
And no luck... I built the kernel with CONFIG_X86_REBOOTFIXUPS set to yes, but that looks to not cover this machine.

We are going to try to wipe the machine and start over with <a href="http://centos.org/">centos 5.3</a>

Note: the machine will happily power off with "shutdown -h now".  It
just won't restart correctly.
