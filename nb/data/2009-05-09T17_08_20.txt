It's pretty obvious that the requirement to have vendors do the
install is still leading to invalid MMSI entries.  Also, I thought
from talking to people who are on the AIS working groups that the
VendorID was supposed to be a unique ID for the actual device like
an Ethernet MAC address.  This clearly is not the case.  Here are the
VendorID's I've seen from about a 1/2 hour of traffic:
<pre>% <b>SELECT DISTINCT(vendorid) FROM b_staticdata;</b>

The fun part is with the SHID... values.  I think that the '@' character is
generally considered the end of string character.  I'm doing a .rstrip(' @'),
but probably I should do a find and truncate with the first '@', but the spec
is unclear if the "@??" is actually a part of the vendor id.

It does look the mothership should generally be distinguishable from
valid lengths. However, the first time someone puts in a really large
DimA or a mothership value under 200000000, this will break.  I just
stored the values decode both ways.
