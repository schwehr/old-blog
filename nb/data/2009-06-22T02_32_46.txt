This works pretty well, but I wanted to give a go at using the lxml event
method of access, since it is likely to be more robust.
<pre><tt><b><font color="#0000FF">def</font></b> <b><font color="#000000">nav_iter</font></b><font color="#990000">(</font>filename<font color="#990000">):</font>
<i><font color="#9A1900">    '''generator for gavia navigation entries'''</font></i>
    <b><font color="#0000FF">for</font></b> i<font color="#990000">,</font> <font color="#990000">(</font>event<font color="#990000">,</font> element<font color="#990000">)</font> <b><font color="#0000FF">in</font></b> <b><font color="#000000">enumerate</font></b><font color="#990000">(</font>etree<font color="#990000">.</font><b><font color="#000000">iterparse</font></b><font color="#990000">(</font>filename<font color="#990000">,</font>events<font color="#990000">=(</font><font color="#FF0000">'end'</font><font color="#990000">,))):</font>
        <b><font color="#0000FF">if</font></b> element<font color="#990000">.</font>tag <font color="#990000">!=</font> <font color="#FF0000">'entry'</font><font color="#990000">:</font>
            <b><font color="#0000FF">continue</font></b>
        entry <font color="#990000">=</font> <b><font color="#000000">parse_entry</font></b><font color="#990000">(</font>element<font color="#990000">)</font>
        element<font color="#990000">.</font><b><font color="#000000">clear</font></b><font color="#990000">()</font> <i><font color="#9A1900"># Free up memory</font></i>
        <b><font color="#0000FF">if</font></b> entry <b><font color="#0000FF">is</font></b> <b><font color="#0000FF">not</font></b> None<font color="#990000">:</font>
            yield entry  <i><font color="#9A1900"># Make this a generator so that we can iterate across entries</font></i></tt></pre>
However, I noticed that it was running really really slow once it got
past about 10000 entries.  I figured out that I could tell it to only
generate "end" events and that left out all the starts.  Then I also
added a clear to the element after I processed it.  That was a huge
speed up, but it still seemed slow.  A quick time test (using the unix time command)
<pre><b>manual search:</b>
  real    0m1.464s
  user    0m1.306s
  sys     0m0.057s
<b>lxml event search</b>
real    0m4.310s
user    0m4.172s
sys     0m0.079s</pre>
Clearly, I need to switch to SAX like parsing if I want to stick with lxml
to find the events and be fast.
