In the multibeam nuts and bolts class, we are parsing an em3002 data file.
Mostly it's parsing binary data in the same byte order, so it's not too hard.
There are some text strings embedded in one of the packets.  Here is the
command line that I used to pull the strings:

That's a pretty confusing looking command, so let me break it down for
you.  You can check the GNU grep command's <a
href="http://www.gnu.org/software/grep/manual/grep.html#Regular-Expressions">Regular-Expressions</a>
section to follow along.  First, I use strings to pull all the ASCII
printable characters.  A lot of these strings are just unlucky chunks
of binary data that happen to map to ASCII characters.  To clean that
up, I use grep to find all strings that are 20 characters or longer.  I
use the extended grep (egrep) to get the full power of regular expressions.
Normal grep is faster than egrep, but is less flexible.
The "." matches any character.  Then the "{<i>n</i>,}" matches
<i>n</i> or more of the preceeding match.  Then I pass the resulting
strings to sort -u to give me a sorted unique list of strings.  

One of the fun parts of unix command lines is that there are often
many ways to accomplish the same thing.  It took me a couple of tries to 
decide on what I wanted to use for the grep string.  Once I realized that
all I want is to get any string longer than 20 characters, I knew that I
can accomplish the same thing with a much simpler strings command:
<pre><b>strings -n 20 0034_20100604_005123_Healy.all | head</b>

Now to parse some of that data.  The default way to start parsing with
C is to use scanf.  This tool is old and crusty, but it works.  Here
is a quick C++ file called text-scan.cpp that demonstrates scanf.

Running the above program demostrates both a successful parse and then
a parse that misses one of the arguments by trying to read a float
when there is only an character ("N").  Scanf (actually string scanf,
sscanf) returns the number of items that it successfully parsed.
<pre><b>g++ -Wall -o text-scan text-scan.cpp -g && ./text-scan</b>
3 (should be 3): 153459 4647.01 N
<!-- -->
Incomplete parse example:
2 (should be 2 out of 3): 153459 4647.01 0</pre>
Obviously, this is not a proper parser for <a href="http://gpsd.berlios.de/NMEA.txt">GGA and other NMEA strings</a>, but it should
give you an idea about how you might write the full parser.

Better yet, you should use regular expressions to parse text data like this.  e.g. <a href="http://www.gnu.org/s/libc/manual/html_node/Regular-Expressions.html">The GNU C library: 10.3 Regular Expression Matching</a>
