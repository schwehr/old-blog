<p>
I have talked about unittesting for C++ <a href="http://schwehr.org/blog/archives/2010-08.html#e2010-08-25T08_35_04.txt">before</a> and got <a href="http://schwehr.blogspot.com/2010/06/which-c-logging-and-unit-test-framework.html">some feedback</a>,
but I never picked a frame work for my code. I've reached the point
where I really have to make a decision and get going. I'm going to do
some quick analysis and see if I can take the plunge. My experience
with python is pretty good, but doesn't make me an expert. Python's 
unittest makes it pretty safe to pick that and just go forward.  There
are other good choices for python, but I'm not worried.  For C++, it's
overwhelming.
</p>
<p>
First a little discussion about requirements.  First, it's got to be
open source.  I'm not investing my time on something that I can't use
whenever I need it.  That also leeds into it having to support C
(which should be a no-brainer for most) and, if possible, ObjC to
support the Mac environment.  It would be nice it it played well with 
continuous integrations systems (buildbot, hudson, etc) so that some
day, I could use one of those.  Any it can't want to fight against the
basic build systems.  And, it needs to be easily packaged.  If I can't
get it into fink and ubuntu, then it isn't going to be around and the
code will not get tested.  Do I care about Windows?  Not really, but
it would be nice if what ever I picked supported that.
</p>
<p>
Next, where can I find out about these systems?  C++ having two plus
characters in its name makes searching annoying.  People often write
cpp (which I still think of as output from the C pre-processor), cxx,
cc, and C.  R and C have the same problem.  Here are some of the
places I looked:

<b>Boost</b>
<p>
I gave a look at the Boost testing environment and used <a href="http://www.ibm.com/developerworks/aix/library/au-ctools1_boost/index.html">Open source C/C++ unit testing tools, Part 1: Get to know the Boost unit test framework</a> from IBM.  It definitely works, but with optimization turned
on, it's really really slow to compile.  I used boost 1.41 from fink.
If you are already using Boost, this is likely a great choice.
</p>
<b>CppUnit </b>
<p>
<a href="http://www.ibm.com/developerworks/aix/library/au-ctools2_cppunit/index.html">Open source C/C++ unit testing tools, Part 2: Get to know CppUnit</a> from
IBM.  I installed cppunit 1.10.2 from fink.  CppUnit compiles test
orders of magnitude fasters.  It seems pretty nice and it isn't such a
monster as bringing it Boost.
</p>
<b>CppTest</b>
<p>
<a href="http://www.ibm.com/developerworks/aix/library/au-ctools3_ccptest/index.html">Open source C/C++ unit testing tools, Part 3: Get to know CppTest</a> from
IBM seemed okay until I realized that it doesn't actually give you
working samples.   I installed CppTest 1.1.1 on Ubuntu 10.10.  Then
I checked <a href="http://cpptest.sourceforge.net/tutorial.html">http://cpptest.sourceforge.net/tutorial.html</a> and there
wasn't a working example either.  There is an example in git,
<a href="http://cpptest.git.sourceforge.net/git/gitweb.cgi?p=cpptest/cpptest;a=blob;f=cpptest/test/mytest.cpp;h=1a497c8e1a152cb7264c854b27fdf0674749d40e;hb=HEAD">mytest.cpp</a>, that I assume works, but if there isn't a good tutorial, I
am not sure it's worth the time.
</p>
