I have been slowly (and I mean the snails are passing me by) working
towards my goal of creating a spatial addition of org-mode.  For part
of that, I would like to be able to pull data from a TCP socket from
GPSD.  I envision being able to select a priority list of position
sources that the program will try to gracefully degrade over.  I have been
reading about emacs lisp (elisp) off and on for the last year and a half.
It's different enough from what I normally do (and I haven't really done 
any lisp since about 1991), that it's challenging.  On top of that, I usually
have only small chunks of time.

I've blogged a bit about elisp in the past, but since it has been so long, I had to go back to the basics.  Start with hello world....hello.el:
<pre><tt>#!/usr/bin/emacs --script
<!-- -->
<font color="#FF0000">(</font>message <font color="#FF0000">"hello world"</font><font color="#FF0000">)</font></tt></pre>
and running this code as a command line script, the <i>message</i> function will
write to standard out.  If you try this inside of emacs with a
"lisp-interaction-mode" buffer, the output goes to the mini buffer.
<pre><b>./hello.el</b>
hello world</pre>
Then I tried to figure out how to work with the command line.  It's possible to use traditional GNU style arguments, but here, I just want to take the <i>host</i> and <i>port</i> that I want to receive text from.  
<pre><tt>#!/usr/bin/emacs --script

Running this demonstrates a couple elisp features.  First,
command-line-args contains the entire raw command line.  This is more
than you might expect.  It's weird that the script name is not there
at the beginning.  The "shebang" replacement is included.

Then I use <i>command-line-args-left</i>, which has the unhandled
portion of the command line in it.  I just learned the <i>nth</i>
function, which is like array access in C-style languages.
<pre><b>./01-command-line.el myhost.schwehr.org 9999 extra args</b>

cdr command-line-args-left: (9999 extra args) 
1st-arg: 'myhost.schwehr.org'
2nd-arg: '9999'</pre>
I then wanted to create a really simple TCP client that just prints
what it receives.  I tried asking on stack overflow: <a
href="http://stackoverflow.com/questions/6162967/simple-tcp-client-examples-in-emacs-elisp">Simple
tcp client examples in emacs elisp?</a> I ended up answering my own
question with a cut down version of <a
href="http://www.emacswiki.org/emacs/TcpClient">TcpClient</a>.  I'll
let you take a look at my answer over on Stack Overflow.

Once I had a super simple network client, I put it together with the
command line handling and created this simple program.  I am impressed
with how fast emacs starts up and it is quite capable of keeping up with
my NAIS feed.  Here is the whole code:

Here is a quick walk through of the program flow.  First, I check to
make sure there are exactly two arguments left after emacs sets itself
up.  I then pull the first arg (number 0) and store it in
<i>listen-host</i> and I save the port number in the same way.

I then define helper functions that start and stop the listener
"process".  Emacs uses the same infrastructure for child processes and
networking.  I use a "filter" called <i>listen-filter</i> to print to
standard out.  The filter is called every time there is input ready
and is handed the data that has come in.  You will notice that the
filter just calls the <i>message</i> function to print the string.

I then start the listener "process" (again, not a real processes) and
sleep for 300 seconds.  The emacs network infrastructure is already
setup to do event handling, so I don't have to worry about creating
some sort of main loop with a <i>select</i> or <i>poll</i> mechanism.

This code isn't what I want in the long run, but it is about the right
complexity for me to start to understand how to get started.
