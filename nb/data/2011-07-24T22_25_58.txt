BODY:
It is almost never true that code only has to be run once.  If that is
true for scientific code, then the scientific method has failed.
Reproducability is then lost.  Being able to show with successful tests
that a code does the right thing is essential, but almost never done.

<a href="http://www.johndcook.com/blog/2011/07/21/software-exoskeletons/">Software exoskeletons</a> [johndcook.com] was referenced on slashdot...

<a href="http://developers.slashdot.org/story/11/07/24/1941242/The-Code-Has-Already-Been-Written">'The Code Has Already Been Written'</a>

Bad code == results in the short term, but those results should be
considered worthless in the long run.  When you are just learning, the
rough/bad code is okay, but if those results are to be used for anything,
you need code that has a least some minimum standards.
