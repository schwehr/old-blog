AUTHOR: Kurt
DATE: 07.31.2011 12:35
DESC: damn
-----
BODY:
<a href="http://ipython.org">ipython</a> 0.11 looks like it is chalk full of new features.  While it
looks amazing, all these changes are giving me serious heart burn.  I
am going to have to package a number of new dependencies and I just
figured out how to get virtualenv working with 0.10.  Worse yet, I am
begging the python community to please stop doing weird non-standard
stuff!  I should be able to run "python setup.py test" and know that
the code mostly works and I shouldn't have to install anything from
the package for that to work.  There needs to be a top level README
or INSTALL file that describes how to do any additional testing.

<a href="http://ipython.org/ipython-doc/dev/install/install.html#installation-from-source">Install instructions</a> and <a href="http://ipython.org/ipython-doc/dev/whatsnew/version0.11.html">What's new in Version 0.11</a>

I'd really like to get the Qt interface going, but that's a hefty
dependency to say the least.

<a href="http://pypi.python.org/pypi/pyzmq">pyzmq</a> (ZeroMQ networking), <a
href="http://pypi.python.org/pypi/paramiko">paramiko</a> (ssh client,
packaged but needs improvement), <a
href="http://pypi.python.org/pypi/Pygments">pygments</a> (colorizing
code, needs package improvements), <a
href="http://pypi.python.org/pypi/readline">python readline</a>, and
exactly which qt python bindings is not obvious from the
documentation.

I will also have to drop python 2.5 support when packaging ipython
0.11, but I get to add python 3.2 support.

Fink packaging contributions more than welcome!
