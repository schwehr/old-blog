I've had the idea of using pypi as the raw source to create a starter
fink package info file or to help with the update process.  I finally
took a couple minutes to give it a go based on the <a
href="http://pypi.python.org/pypi/yolk">Yolk</a> python package.  I
got a proof of concept done, but I'm not sure that I am on the right
track.  I posted a ticket with the Yolk developer, <a
href="http://blog.cakebread.info/">Rob Cakebread</a> asking for
examples of how he thinks the yolk API should be used:

<a href="https://github.com/cakebread/yolk/issues/2">https://github.com/cakebread/yolk/issues/2</a>

In looking around, I realized that perhaps yolk isn't the best platform for
this.  Rob points to <a href="http://code.google.com/p/g-pypi/">g-pypi</a>:
<pre>g-pypi creates ebuilds for Gentoo Linux using information in PyPI
(Python Package Index).</pre>
That is exactly what I am trying to do for fink and it was a 2010 Google
Summer of Code project.  Looking into g-pypi, I realized that the code is 
also based on yolk and by Rob, so yolk looks to be the way to go.  The
one thing that I was bummed to see is that he is using the Cheetah templating
library rather than python's str ".format" method.

I got a bunch turned around in my initial inspection of yolk, but
after a bit here is what I came up with for two examples.  First with
SQLAlchemy:
