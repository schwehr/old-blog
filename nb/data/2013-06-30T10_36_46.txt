In going through autoconf setup for mb-system, I have started feeling
much better about autoconf.  I think that one of the main things
missing are a nice collection of simple examples.  I wanted to see
what it looked like to setup an example of the bare minimum to test
byte order.  Here is what I did.

First, create a file called configure.ac (formerly known as configure.in):
<pre>AC_PREREQ([2.65])
<!-- -->
AC_INIT([endian],[1.0])
<!-- -->
AM_INIT_AUTOMAKE
dnl AM_MAINTAINER_MODE
AM_PROG_CC_C_O
<!-- -->
AC_C_BIGENDIAN
<!-- -->
dnl AC_CONFIG_HEADERS([config.h])
AC_CONFIG_FILES([Makefile])
<!-- -->
AC_OUTPUT</pre>
Note that "dnl" is the start of comment designation (aka Do Not Load).

This basically says that we have an autoconf 2.65 based configuration
for a project called "endian".    We want to use automake to build C
programs and that we need to know the endian-ness of the machine.

Next, I need an automake input file, Makefile.am, that says how to
build our endian.c code.
<pre><font color="#009900">bin_PROGRAMS =</font> endian
<font color="#009900">endian_SOURCES =</font> endian.c</pre>
And now for the source code:
<pre><b><font color="#000080">#include</font></b> <font color="#FF0000">&lt;stdio.h&gt;</font>
<!-- -->
<font color="#009900">int</font> <b><font color="#000000">main</font></b><font color="#990000">(</font><font color="#009900">void</font><font color="#990000">)</font> <font color="#FF0000">{</font>
<b><font color="#000080">#ifdef</font></b> WORDS_BIGENDIAN
  <b><font color="#000000">printf</font></b><font color="#990000">(</font><font color="#FF0000">"big</font><font color="#CC33CC">\n</font><font color="#FF0000">"</font><font color="#990000">);</font>
  <b><font color="#0000FF">return</font></b> <font color="#993399">1</font><font color="#990000">;</font>
<b><font color="#000080">#else</font></b>
  <b><font color="#000000">printf</font></b><font color="#990000">(</font><font color="#FF0000">"little</font><font color="#CC33CC">\n</font><font color="#FF0000">"</font><font color="#990000">);</font>
  <b><font color="#0000FF">return</font></b> <font color="#993399">0</font><font color="#990000">;</font>
<b><font color="#000080">#endif</font></b>
<font color="#FF0000">}</font></pre>
To set this up, create an autogen.sh script:
<pre><tt><i><font color="#9A1900">#!/bin/bash</font></i>
<!-- -->
autoreconf --force --install</tt></pre>

That's great and it works, but the build line is pretty long.  We can
use a config.h C include file to track all the defines rather than -D
flags in the gcc compile line.

First, add this line to the configure.ac right after AC_CONFIG_FILES:
<pre>AC_CONFIG_HEADERS([config.h])</pre>
At the top of endian.c, add this include:
<pre><b><font color="#000080">#include</font></b> <font color="#FF0000">"config.h"</font></pre>
Then build again:
<pre><b>./autogen.sh
./configure
make </b>
make  all-am
gcc -DHAVE_CONFIG_H -I.     -g -O2 -MT endian.o -MD -MP -MF .deps/endian.Tpo -c -o endian.o endian.c
mv -f .deps/endian.Tpo .deps/endian.Po
gcc  -g -O2   -o endian endian.o</pre>
The new config.h file contains this c-pre-processor (cpp) setup:
<pre><tt><i><font color="#9A1900">/* Define WORDS_BIGENDIAN to 1 if your processor stores words with the most</font></i>
<i><font color="#9A1900">   significant byte first (like Motorola and SPARC, unlike Intel). */</font></i>
<b><font color="#000080">#if</font></b> <font color="#008080">defined</font> AC_APPLE_UNIVERSAL_BUILD
<b><font color="#000080"># if</font></b> <font color="#008080">defined</font> __BIG_ENDIAN__
<b><font color="#000080">#  define</font></b> WORDS_BIGENDIAN <font color="#993399">1</font>
<b><font color="#000080"># endif</font></b>
<b><font color="#000080">#else</font></b>
<b><font color="#000080"># ifndef</font></b> WORDS_BIGENDIAN
<i><font color="#9A1900">/* #  undef WORDS_BIGENDIAN */</font></i>
<b><font color="#000080"># endif</font></b>
<b><font color="#000080">#endif</font></b>
</tt></pre>
