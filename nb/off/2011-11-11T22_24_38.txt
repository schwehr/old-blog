I'm repeating myself here from Sept. and Oct. 2008.  See my links to prior blog
posts at the bottom of this post.

This is a reminder to the sonar community about the "Generic Sensor Format":
<pre> * Copyright (C) Science Applications International Corp.</pre>
No where in the code does SAIC give anyone permission to use the GSF code.
This is <b>NOT</b> a license for using the code:
<pre>The GSF format, and code to read it, is open source and is
updated regularly to keep current with new technologies and uses. New
releases of the GSF library are generally made once or twice each
year. However, the frequency of updates to GSF in any particular year
depends on technology advances within the community. New GSF releases
provide an expansion of capability while preserving all previous
capability.</pre>
So if you use GSF, you are violating US Copyright Law.  Please join me
in asking SAIC to actually put a software license (I'd recommend a BSD
or LGPL license).  I specifically brought this up in the GSF workshop
at Shallow Survey 2008 and asked SAIC to put a license in the code.

If you read the GSF Spec, you will see this:
<pre>1.3.1	Usage of GSF outside of DoDBL
This specification describes the form of data being exchanged within
the DoDBL.  The format described in this specification is intended,
however, to be of use outside the DoDBL.  Using this format will
increase the efficiency of data transfer between the agency's internal
archive and the DoDBL and, perhaps, between agencies without direct
access to the DoDBL. For use of this specification outside the DoDBL,
Transmittal files and Metadata files are optional, although their use
is encouraged.  Many of the elements of the Metadata file may be most
accurately described immediately after the data have been collected.
From the moment the data are collected, adoption of the Metadata file
as a method of maintaining important descriptive information can
significantly enhance the data's long-term usability.</pre>
All it would really take would be a "license: bsd" or "license:
apache" or "license: lgpl v3" put there by SAIC, and I would be much
more comfortable with the community using this code.  

The reality is that I should not have put MB System in Fink without 
this license issue being resolved.  And MB System definitely can not 
go in the main packages because of this issue unless I ripped out GSF
support.  If I did that, I know people would be frustrated and
consider MB System broken.

Some of the
other issues that I brought up back in 2008:
<ul>
<li>No unit tests</li>
<li>No sample files</li>
<li>No build system</li>
<li>A non-standard release layout in the zip</li>
<li>A non-standard numbering scheme for the zip</li>
</ul>
Those are the issues that I remember.  If the license were fixed,
then there would a legal chance for me to work with and contribute 
to GSF.
